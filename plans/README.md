## Why plan 001 was shipped

The brief asked for the highest-leverage plan that is a real user-facing feature
or a substantial correctness fix, which the repo's own tests can fully verify.
Plan 001 wins on every count:

- **Two audit passes found it independently.** The correctness/security pass and
  the performance/tests pass both reported it, and the vetting re-read confirmed it
  in code:
  - `src/app/canvas.tsx:955-957` flushes every 60 ms while anything changes, so
    about 16 messages/s during a drag or freehand stroke.
  - `src/worker/room.ts:441` admits 240 updates per minute **per board**, shared by
    every tab, then closes the sender with 1013. The client reconnects, re-sends on
    `init`, and is closed again until the window rolls over.
- **It hits the core product path.** About 15 s of normal drawing disconnects a tab,
  in the middle of a collaborative interview.
- **It also removes cost and a dependency.** Every canvas message paid two D1 round
  trips first (`request-limits.ts:58-66`), and a D1 outage closed every editing
  socket.
- **It is fully verifiable in Vitest.** The room's socket handler is driven
  directly, and four of the five new tests fail on the base commit.

Plan 002 is the runner-up. It is also a real, verified bug, with smaller everyday
impact. Plan 005 is the best feature, but ROADMAP.md asks for a pilot baseline
and coordination with system-design-chatgpt before building it, which an
autonomous run cannot clear.

## Direction suggestions (options, not ranked against bugs)

- **Finish and recap in the sidebar interviewer** (plan 005). This is the ROADMAP
  "Now" slice: a goal, a timebox, start and end checkpoints, and a recap grounded in
  `RUBRIC`. Every part already exists, but the pieces are not connected:
  - `RUBRIC` is MCP-only (`src/worker/rubric.ts`, `mcp.ts:751-774`).
  - The panel has no end state (`interviewer-panel.tsx:266-325`).
  - The snapshots endpoint already exists (`index.ts:202-207`).

  Trade-off: ROADMAP.md lines 22 and 30 ask for a pilot baseline and coordination
  with system-design-chatgpt first.

- **Read-only snapshot graph and checkpoint comparison.** Snapshots are raw element
  arrays in R2 (`room.ts:790`), and `graphView` already turns elements into a
  semantic graph (`room.ts:636-642`). A `get_snapshot`/compare tool would make recap
  feedback "link to observed decisions", and it unblocks the ROADMAP "Next" drill.
  Effort M.
- **An MCP `session_recap` prompt** that reuses the same recap rules, so Claude Code
  and Codex users get the same outcome (`mcp.ts:760-802` has review, next step and
  estimates, but no end-of-session prompt). Effort S. Quality can only be judged
  in a real host.
- **Not yet: server-side session records.** They need retention, erasure and
  ownership decisions that `docs/openai-plugin-readiness.md` leaves open.

## Findings considered and rejected

- **Capability keys in `?k=` URLs end up in Workers observability logs.** The share
  link itself is `/d/<id>?k=<key>` by design (README, `docs/design.md`), and the
  correctness pass rated this MED confidence pending a check of what Workers Logs
  store. Investigate the deployed log fields before planning, rather than changing
  the capability protocol.
- **R1–R5 from `docs/reliability-audit.md`** (duplicate IDs, missing template image
  bytes, library-capability events, numeric index, reconnect winners) are already
  fixed in #54 and have regression tests.
- **Non-atomic snapshot and creation cross-store writes, the 7-day tombstone GC,
  and webhook DNS-preflight limits** are documented design decisions in
  `docs/design.md` and `docs/reliability-audit.md`.
- **Unbounded auto-snapshot retention.** This is real storage growth, but pruning
  auto snapshots can invalidate an `undoSnapshotId` an agent still holds. It needs a
  product decision, so it is deferred until after plan 002 separates the named and
  auto listings.
- **Splitting `Canvas` (1,060 lines) or `Scene`.** `Scene` is deliberately cohesive
  (`docs/untangle-decisions.md`). A `Canvas` split should follow characterization
  tests of the sync helpers, not come first.
- **webcola deep imports and the stale `minimumReleaseAgeExclude` entries.** They are
  stable and covered by tests, and are low value on their own.
- **Archiving `docs/reliability-audit.md` and `docs/untangle-decisions.md`.** That is
  docs-only work. It is worth doing alongside plan 004, which removes the CI steps
  those docs explain.
